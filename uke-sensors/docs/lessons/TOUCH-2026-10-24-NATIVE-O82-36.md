# TOUCH-2026-10-24-NATIVE-O82-36

- Date: 24 October 2026.
- Environment: Xiaomi Pad 7 with the bootloader-selected O82-36 panel, Fedora 44 KDE native-display trial; boot journal read through TWRP and host C++ fixture.
- Evidence: the native MSM display produced a visible desktop and registered `msm-kmsdrmfb`. `uke-touchscreen.service` exited repeatedly with `O82 kernel panel-reset provider is not ready`. The installed touch daemon searched only for `xiaomi,o82-42-02-0b`, while the native trial exposes the O82-36 panel's `touch_reset_state`.
- Practical consequence: admit either exact O82-36 or O82-42 reset provider, retaining the unique-provider and generation guards. The firmware-framebuffer admission remains separate.
- Package result: `uke-touchscreen-0.1.0-17.fc44.aarch64.rpm` passed its AArch64 RPM checks. Its binary was copied to the installed Fedora filesystem through TWRP and verified by SHA-256. The next boot stopped before Fedora wrote a new journal. The installed ext4 filesystem separately recorded a bad block bitmap checksum before this binary was installed.
- Tablet result, 25 October: after an offline ext4 repair with e2fsck 1.47.3, the same Fedora 44 KDE image reached the desktop. Finger input worked. The USB diagnostic console reported `uke-touchscreen.service` active and showed contact and release frames from the daemon. The kernel journal registered `msm-kmsdrmfb`; the grey screen cleared after roughly 2–3 seconds.
- Uncertainty: native panel-reset recovery, refresh transitions and suspend/resume still need tablet tests. The brief grey screen during display handoff remains a separate observation; its cause is unconfirmed.
- Next validation: finish KDE first-boot setup, check the screen keyboard and login, and test panel-reset recovery separately.
